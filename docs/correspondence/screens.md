### Segments, rails and filters (D-30)
- One rail item, **Email**. Segments: **All**; **Assigned to me** (`ownerId` is the viewer, D-72); **Needs action** (`triage = needs_action`); **Waiting** (`triage = waiting`); **Overdue** (`sla = overdue`); **Unmatched** (no linked record); **Follow up** (a follow-up date is set, D-72). Each non-All segment is one condition and a quick filter; a filter that is none of these selects no segment.
- Other quick filters: **Has attachments**, **Confidential** (`visibility = restricted`).
- **Reading view pane (D-65):** the same views with counts (one `View is …` condition), **Tag · Object type** (`kinds` is any of RFI / Drawing / Submittal / Change order / Untagged), **Object ID** (`recordIds` is one record with mail), **Sender company** (`companyText`), **Date** (`activityWithin` is today / 7d / 30d / 90d, cumulative buckets). Hidden columns; the Filter panel shows and edits them; the segments hide while the pane is open.
- Rails not in the MVP: Drawings › Revisions, RFIs › Drafts, Configure.

### Email screen columns (dimension in `status-model.md`)
Subject · Letter (the correspondence number and type, D-78) · Linked record (code and revision; *Link to record* action when empty) · Files (every file on the thread, searchable, D-79) · From / company · Owner (D-72) · Triage (`triage`) · Due (`sla`, date) · Follow up (D-72, date) · Delivery (`delivery`, weakest recipient) · Last activity · Promoted (`promotion`, link) · Cost impact (`canSeeCost` roles) · Actions (frozen right).
