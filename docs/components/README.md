# Component backlog (candidates)

Components the prototypes need that the design system doesn't have on either side (no Figma component, no library code). Each goes through the stages below; the policy is D-15 in `docs/4-decisions.md` and the rules are in `CLAUDE.md` › "Module screens and candidate components".

**Stages:** `proposed` (doc only) → `candidate` (built in `src/candidates/<Name>/`, used by a prototype) → `figma` (drawn as a component in Figma, variables bound, design iterating) → `library` (moved to `../linarc-design-components/src/componentsV2/<Name>/` with stories, README and `.figma.js`; P-row logged) → `connected` (Code Connect published; candidate folder deleted).

Before proposing a new one, check: the library (`@/componentsV2`, `@/components`), the Figma V3.2 component list, and this table. Prefer extending an existing component (logged as a P-row) when the new thing is a variant of it. Candidates that the first module closed as compositions (finding card, decision panel, activity timeline, qualification card) or extensions (multi-select, tab navigation, progress stepper) are listed in `linarc-prototypes/docs/components/README.md`; check it before proposing something similar.
